How Vantage works

Same engine behind the CLI and this interface.

Command line

vantage scan 192.168.1.0/24 --scope homelab.json --authorized
vantage scan 10.0.0.5 --profile deep --open-report
vantage ui                        # this page
vantage history                   # past scans
vantage show <scan-id> --full    # finding detail
vantage findings --severity high  # cross-scan query
vantage report <scan-id>          # re-render to HTML/MD/JSON
vantage doctor                    # toolchain check
vantage audit --tail 30           # authorisation log

Severity versus confidence

These are two separate axes, and keeping them apart is the point. Severity is how bad it would be if true. Confidence is how sure this scan is that it is true.

  • confirmed a check returned a positive result (an NSE script said VULNERABLE, a TLS handshake succeeded on TLS 1.0, a port is open).
  • likely a strong signal that needs one manual step to confirm.
  • possible a heuristic hit — nikto output, an end-of-life banner, a version comparison. Verify before acting.
  • informational context, not a weakness.

What it will not do

  • Run without an explicit authorisation statement.
  • Leave a declared scope — a target outside the scope file is refused before any packet is sent.
  • Use credentials, attempt logins, or run exploitation tools.
  • Pass --script-args unsafe=1 to nmap; several NSE scripts can crash fragile services.
  • Claim "vulnerable" from a version banner alone — those are reported as possible.

Exit codes

0scan completed
1error during the run
2refused — authorisation or scope
3a required tool is missing
4--fail-on threshold met (CI gate)

Where things are stored

~/.local/share/vantage/

  • vantage.db — scan history and findings (SQLite)
  • reports/<scan-id>/report.{html,md,json}
  • logs/audit.jsonl — every authorisation decision, including refusals

Scope files

A JSON, TOML or plain-text list of the networks an engagement covers:

vantage scope new --name homelab --targets 192.168.1.0/24 10.0.0.0/25 -o homelab.json
vantage scope check homelab.json

Plain text works too — one network per line, # for comments. The scope file's networks are hashed into every report as a fingerprint.

Legal

Port scanning is legal in most places when you have permission and illegal when you do not. In Germany that is §202a–c StGB (Ausspähen und Abfangen von Daten); elsewhere the equivalents are the CFAA (US) and the Computer Misuse Act (UK).

A port scan is not "harmless traffic". It touches systems you do not administer. Keep written authorisation on file — the scope, the dates, the permitted techniques — and stay inside it.

Authorization statements, scope fingerprints and target lists are written to the local audit log for exactly this reason.
